Architecture

High-level design: the request path, where authority sits, authentication, and deployment.

Three hops, no database

The consequence of having no persistence layer is that business rules live in service classes as DQL strings. Searching for a behaviour usually means grepping for a fragment of DQL, not for an entity or a repository method.

Request lifecycle

  1. A page calls api.get('/users/profiles'). The axios instance prepends http://localhost:8080/api and attaches Authorization: Bearer … if a token is in localStorage.
  2. The matching @RestController receives it. Controllers are thin — they unpack parameters and delegate immediately.
  3. The service builds a DQL string or a REST object path, and calls RestClient with an auth header obtained from DctmAuthService.
  4. dctm-rest returns Documentum's JSON envelope — entries[].content.properties. Services unwrap that shape by hand into plain Map objects.
  5. The controller returns the map; Jackson serialises it. There are almost no response DTOs — only AuthResponse and LoginRequest exist.

Authentication and authorisation

Two distinct identities

IdentityPurposeMechanism
Service accountAlmost every repository operation DctmAuthService obtains a login ticket via Basic Auth and caches it for 9 minutes (tickets expire at 10)
End userLogin, and impersonation for user-scoped reads OTDS token; generateUserLoginTicket lets support act as a named user

Where authorisation is enforced

Access control is client-side only. MainLayout reads admin_role out of localStorage and renders an "Access Denied" panel unless the value is Super Admin or Local Admin. No Spring Security is configured and no endpoint checks a role. Anyone who can reach port 8080 can call all 102 endpoints directly.

Treat the role gate as navigation convenience, not a security boundary. Do not rely on it when adding an operation that must be privileged.

The two roles differ in what the sidebar shows and in a few in-page checks:

RoleSees
Super AdminEverything, including NABARD Department Management and SFS
Local AdminScoped by their own office type — HO Vertical Management is hidden for RO/TE admins and RO/TE Department Head Assignment is hidden for HO admins. SFS is visible only to HRMD Local Admins.

Session lifetime

Idle handling is entirely front-end: useIdleTimeout(30000, 1800000) in MainLayout warns after 30 minutes of inactivity and logs out 30 seconds later by clearing localStorage and navigating to /login. The backend holds no session state, so a stale tab simply starts failing rather than being rejected.

CORS is declared per controller and is not uniform. Most allow both localhost:5173 and localhost:5174. SettingsController allows only 5173, and TransliterateController allows *. If the dev server starts on 5174 — which it does whenever 5173 is taken — Settings silently fails while everything else works.

Environments

Configuration is split by Spring profile, selected with spring.profiles.active (currently azure):

FileUse
application.propertiesShared settings and the active-profile switch
application-azure.propertiesAzure environment

Environment-specific hosts and the OTDS token URL are overridden per profile. Service-account credentials can be supplied through DCTM_SERVICE_USERNAME / DCTM_SERVICE_PASSWORD environment variables; defaults sit in the properties files.

Packaging and deployment

  • Backend builds to a war named neoadminBackend, with ServletInitializer present for deployment into an external Tomcat. spring-boot-starter-tomcat is declared, so it also runs standalone with mvn spring-boot:run.
  • Frontend builds with Vite to static assets served under the base path /neoadmin/. That base is set in vite.config.js and mirrored by the router's basename — both must agree or deep links break.
  • services/dctm-rest/ in this repository is the Documentum REST war. It is reference only and must never be modified; its OpenAPI spec at services/dctm-rest/docs/rest.yaml is the authority for what the repository layer accepts.
