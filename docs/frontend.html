The API layer

The entire client is 19 lines:

const api = axios.create({
  baseURL: "http://localhost:8080/api",
  headers: { "Content-Type": "application/json" },
});

api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

The backend URL is hardcoded to localhost:8080. There is no environment variable and no proxy configuration in vite.config.js. Any non-local deployment depends on something outside this file — a reverse proxy, or an edited build. Do not assume the built bundle will reach a remote backend as-is.

There is no response interceptor, so there is no central handling of 401, no retry and no error normalisation. Every call site does its own .catch, and the prevailing style is .catch(() => {}) — failures are frequently swallowed.

Session and role handling

localStorage holds two keys: user (the profile object) and token (the OTDS token). The role is read defensively in several places because the shape varies:

const storedUser = JSON.parse(localStorage.getItem('user') || '{}');
const adminRole  = storedUser.properties?.admin_role || storedUser.admin_role || null;

MainLayout renders "Access Denied" unless the role is Super Admin or Local Admin. Sidebar filters navigation by role, with two extra rules: HO Vertical Management is hidden from RO/TE Local Admins, RO/TE Department Head Assignment from HO Local Admins, and SFS is Super Admin plus HRMD Local Admins only.

src/data/nabardMetadata.js (1,057 lines) is the vocabulary the whole portal is built on:

DESIGNATION_OPTIONSDA, AM, MGR, AGM, DGM, GM, GM(OIC), CGM, DMD, CHAIRMAN
USER_GRADESgroup_b(0) … grade_f(6), including grade_e(oic)(5)

DDM_DISTRICTSDistricts per location, for DDM users

Designation and grade are kept in step by two mirrored maps in EditUserProfileModal (DESIGNATION_GRADE_MAPPING and its reverse). Adding a designation or grade means editing both, plus USER_GRADES. The CMS also consumes this grade vocabulary, so the blast radius extends beyond this repository.

Utilities

utils/dateFormat.jsparseDocumentumDate (accepts ISO-8601 UTC from xCP REST and the day-first DFC form) and formatDateTime → 16/01/2026 05:44:00 PM. Added for NEO-247 because the portal had no date helper and the CMS one could not be shared

Hooks

  • useIdleTimeout(warningMs, logoutMs) — timer refs, activity listeners, countdown. Called from MainLayout as (30000, 1800000): warn 30 s before a 30-minute idle logout.
  • useQueryHistory() — persists DQL console history.

Build

cd frontend
npm install
npm run dev       # Vite dev server — 5173, or 5174 if 5173 is taken
npm run build     # static assets under base /neoadmin/
npm run lint      # eslint flat config
npm run preview

npm run lint currently reports one pre-existing error: handleDepartmentChange is assigned but never used in EditUserProfileModal.jsx. It is on SFS and unrelated to recent work — do not treat it as a regression from your change.
