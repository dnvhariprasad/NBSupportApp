Running locally

Ports, start and stop, and how to be sure you are looking at the instance you just changed.

Prerequisites

  • Java 17 — set in pom.xml; a newer JDK may compile but is not what this targets.
  • Maven, installed globally. There is no wrapper — mvnw is gitignored, so start_services.bat falls back to mvn.
  • Node.js LTS.
  • Network reach to 172.172.20.214:3030. The backend starts without it but every request fails, so an unreachable repository looks like a broken application.

Start

Both at once

start_services.bat     # stops anything on 8080/5173 first, then starts both
stop_services.bat      # kills whatever is listening on 8080 and 5173

Separately — preferred while developing

cd backend
mvn spring-boot:run          # → http://localhost:8080
cd frontend
npm install                  # first run only
npm run dev                  # → http://localhost:5173/neoadmin/

The URL needs the /neoadmin/ path. vite.config.js sets base: '/neoadmin/' and the router uses the same basename. Opening http://localhost:5173/ does not serve the app — Vite answers with a note about the public base URL.

Verify it is up

curl -s -o /dev/null -w "backend  %{http_code}\n" "http://localhost:8080/api/groups/by-prefix?prefix=ecm_&size=1"
curl -s -o /dev/null -w "frontend %{http_code}\n" "http://localhost:5173/neoadmin/"

Allow generous timeouts. The first backend call after startup opens a Documentum session and can take several seconds. A short curl timeout makes a healthy backend look dead — this has already caused one wrong diagnosis.

Two clones — the trap that costs the most time

A second clone of this repository exists at D:\NBSupportApp, outside the workspace and usually on a different branch. If its dev server is already running, it holds port 5173, and the one you start from D:\NB NEO\NBAdminApp silently moves to 5174.

You then edit one checkout and test the other, and your changes appear to have no effect.

Which clone is on which port?

Ask the dev server for a file you know exists in only one of them:

curl -s http://localhost:5173/neoadmin/src/utils/verticalHead.js | head -3
curl -s http://localhost:5174/neoadmin/src/utils/verticalHead.js | head -3

The clone that has the file returns JavaScript; the other returns the SPA fallback HTML. Or list the listeners and match the PID:

Get-NetTCPConnection -State Listen -LocalPort 5173,5174 |
  Select-Object LocalPort, OwningProcess

stop_services.bat only clears 8080 and 5173. A stray server on 5174 survives it and will still be serving stale code afterwards.

CORS and the port you land on

Most controllers allow both localhost:5173 and localhost:5174, so a shifted port mostly works. Two do not:

  • SettingsController allows only 5173 — Settings calls fail on 5174 while everything else succeeds.
  • TransliterateController allows *.

If one feature fails with a CORS error and the rest of the app is fine, check which port you are on before looking anywhere else.

Signing in

You need an account with admin_role of Super Admin or Local Admin. Anything else lands on the "Access Denied" panel from MainLayout — that is the role gate, not a failed login.

The session is front-end only and idles out after 30 minutes, with a 30-second warning. After a long pause you will be back at the login screen with no server-side error to explain it.

Build for deployment

cd backend  && mvn clean install    # → target/neoadminBackend.war
cd frontend && npm run build        # → dist/, served under /neoadmin/

The backend war carries ServletInitializer for an external Tomcat. Note that the frontend hardcodes http://localhost:8080/api in src/api/axios.js, so a deployed bundle needs a reverse proxy or an edited base URL — there is no environment variable for it.

Diagnosing without the UI

With no test suite, the DQL console is the quickest way to check repository state:

curl -s -X POST http://localhost:8080/api/query/execute \
  -H "Content-Type: application/json" \
  -d '{"dql":"select object_name, office_type, department_short_code from cms_user_profile where user_login_name = '"'"'cto.dit'"'"'"}'

And to inspect a user's group membership:

curl -s "http://localhost:8080/api/groups/by-user?username=cto.dit"

Both hit the shared UAT repository. Reads are safe; PATCH and group POST/DELETE change data other people are using. Snapshot before you write, and restore after.
